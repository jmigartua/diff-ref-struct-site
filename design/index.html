Design: open questions

Design: open questions

What has to be decided before the core is written, with the options seen today and a first opinion on each. None of this is decided; each question closes with a logged decision after phase 0.

The shape: core, app, ecosystem

As in difes: the core holds all the crystallography and the refinement, has no user interface, has a test for every feature and a command-line path to every feature. The app is a native Mac window around it and holds no physics. The ecosystem is this site, its data and its tools. One repository holds the three (L003).

Q1 · The language of the core

  • Rust. The same language as Tauri's side, so the core links straight into the app with no server or interpreter to ship; fast; one binary for the command line. Fewer crystallographic libraries to lean on.
  • Python with compiled kernels. The GSAS-II route and the difes habit; quick to write and to script; the interpreter has to be shipped inside the app.
  • A Fortran or C++ kernel under either of the above. Where FullProf's and GSAS's numerics come from.

First opinion: Rust for the core, with Python bindings for scripting, because a refinement program lives or dies by the speed of its inner loop and the Mac app is best as one signed binary. To be confirmed against the feature matrix.

Q2 · The space groups

R12 asks for the complete set with all the needed information. The tables can be generated from generators (Hall symbols) rather than typed in, and checked against an independent source (the International Tables, Vol. A; spglib; cctbx's sgtbx) for all 230 groups and their settings. Magnetic groups (the 1651 Shubnikov groups) are needed if magnetic refinement is in scope, which the study will tell.

Q3 · The control file

R13 and R14 ask for a GUI that writes the control file and an editor made for it. That supposes a control file that a person can read and write. The choice: adopt an existing format (FullProf's .pcr, TOPAS's .inp) or define a new, readable one and import the others. First opinion: a new format designed for reading and diffing, with importers for .pcr and GSAS-II project files, so that existing refinements open in the app.

Q4 · The editor

A text editor made for the control and output files: syntax colouring, completion of keywords and of the names of phases and atoms, inline errors from the core's parser, folding by phase and pattern, a structure outline, jump from an output line to the parameter it refers to. A web editor component (CodeMirror 6) inside the Tauri window gives all of that with a language mode written for the format.

Q5 · The live plot

R08: as in FullProf's WinPLOTR, the observed, calculated and difference curves and the reflection markers redrawn after every cycle, with the agreement factors. The core must therefore report each cycle as an event (parameters, curves, R-factors) that the app draws without waiting for the end. The same event stream feeds a history of the refinement that can be scrolled back.

Q6 · The Mac app

R01: a document-based app (one refinement project per window or tab), the full menu bar with the standard entries and shortcuts, Settings, Recent items, Undo and Redo of every change to the model, a source list, an inspector and a command palette, as in the difes shell.

Beyond the brief

R15 asks for more than the brief lists. Candidates to weigh against the study: joint refinement of X-ray and neutron patterns; sequential and parametric refinement over temperature or pressure series; Le Bail and Pawley fits; indexing; quantitative phase analysis with amorphous content; restraints and rigid bodies; magnetic structures; time-of-flight neutrons; fundamental-parameters peak shapes; texture; size and strain; export of the result as a CIF ready for deposition; a refinement history that can be replayed; and a test ledger that reproduces published refinements, as difes reproduces FOCUS.

On this page

    What this is

    The working site of one project: to build a Mac app for Rietveld refinement of powder diffraction data, after a study of the programs the community uses for it. It holds the brief, that study, the design, a dated log of every step, the release notes and the manuals of the core and the app.
