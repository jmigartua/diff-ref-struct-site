L0202026-10-09decision

The proposal's open questions decided: constant wavelength first, Levenberg–Marquardt, our own control file

Josu answers the six questions the proposal draft (L019) left open, taking the recommendations made in the conversation: - TOF (P05): version 2. Version 1 is constant wavelength only (laboratory X-rays, synchrotron, reactor neutrons). - Joint X-ray + neutron refinement (P06): version 2, since it needs the multi-pattern machinery of version 2; the version 1 data model allows several patterns from the start. - Rigid bodies and TLS (P41): version 2. Distance, angle and linear restraints stay in version 1. - The minimiser (P42): Levenberg–Marquardt with SVD against correlations, as GSAS-II. With correlated parameters it is more robust than FullProf's Gauss–Newton with relaxation factors, which need hand tuning. - The control file (P47, design question Q3): a new readable text format of our own, written and read by the core, with an importer for FullProf .pcr files so that FullProf users bring their work. - The reference refinements that define "version 1 is done": the four tutorials proposed, Y2O3, MgAl2O4, Co-doped YBCO and quantitative phase analysis, each to be reproduced within its esd's from the command line and the app.

Set aside: TOF, joint refinement and rigid bodies in version 1, which keeps version 1 to what a FullProf user does today on constant-wavelength data; Gauss–Newton with relaxation factors; the .pcr itself as the app's file format (fixed-format, numeric codewords, not readable without the manual). Still open: Q1, the language of the core, and with it P48 (Python scripting in version 1 or 2).

The proposal drafted: 59 features, 38 in version 1

The last item of phase 0, written as a draft for Josu to decide, not as a decision. The app's feature set is drawn from the FullProf inventory (199 entries, L017) and the GSAS-II gap list (36 gaps, L018). There are 59 features in 11 groups; each names its sources (inventory entries, gaps, brief requirements), and build.py stops if a named entry does not exist. Draft tiers: 38 in version 1, 11 in version 2, 10 later; the L012 "later" list stays outside both versions. - Version 1: what a FullProf user does today on constant-wavelength data (laboratory X-rays, synchrotron, reactor neutrons), from pattern to CIF, one or several phases, quantitative analysis, Le Bail, constraints, limits, distance/angle/linear restraints. It runs inside the app the brief asks for: one project document with undo, a readable control file with .pcr import, builder, editor, live plot per cycle, background set on the plot. - Where GSAS-II does it better, the draft takes the GSAS-II way: named parameters instead of numeric codewords, constraint equations, the s.u. of any expression, accept/reject and a refinement history, vendor formats read directly, publication plots. - Version 2: TOF, joint multi-pattern refinement, sequential and parametric refinement, rigid bodies and TLS, anisotropic size and strain, texture beyond one axis, Pawley, refinement diagnostics, Python scripting. - Proposed test for "version 1 is done": the command line and the app reproduce four reference refinements from manuals/fullprof/ (Y2O3, MgAl2O4, Co-doped YBCO, the quantitative-analysis tutorial) within their esd's.

Open for Josu: TOF, joint X-ray + neutron and rigid bodies in version 1 or 2; the minimiser (Levenberg–Marquardt with SVD, or Gauss–Newton with relaxation); the control-file format (Q3); the reference refinements.

L0182026-10-09finding

GSAS-II gaps re-checked against FullProfAPP: none closed, five narrowed

The 36 gaps of L014 were re-checked against the FullProfAPP manual (version 1.3.3, June 2025; first release 1.0.0, July 2023; Windows and Linux only), which L014 could not reach. Each gap was also checked against the 41 capabilities added to the FullProf inventory in L017. The manual closes none and narrows five; each narrowed row now says what FullProfAPP does and what remains of the gap:

  • Automatic background: FullProfAPP finds points by asymmetric least squares and fits a Chebyshev series to them. What remains: other functions, and the automatic background used as a fixed background.
  • Project file: a .fpapp file saves the interface state and each run goes to a numbered folder. What remains: data, model, constraints, results and covariance in one file.
  • Python scripting: documented modules edit .pcr files and parse .sum, .prf and .mic files. What remains: running refinements from a script, the covariance, constraint equations.
  • Publication plots: plots can be saved from a context menu. What remains: named vector and program formats.
  • Sequential results: exported as XY text. What remains: a multi-block CIF of the series.

None of the L017 additions closes a gap. For example, spherical harmonics in FullProf are for anisotropic strain, not for preferred orientation, and the stored background profiles are not GSAS-II's background peaks. The gap list stays at 36.

Added within the scope, among others:

L0112026-10-09finding

GSAS-II read on the common template

GSAS-II read from its own source and documentation: the GitHub repositories GSAS-II (commit c13e730) and GSAS-II-tutorials (commit 924e9eb), which is the source of the tutorial site Josu pointed to. That site itself is blocked by this session's network, so nothing needs downloading into manuals/. Each claim on the page links to the line it comes from. Findings that matter for the design: - There is no control file. Everything lives in one .gpx project shown as a data tree, and the same file is driven from Python (GSASIIscriptable). Every parameter has a name p:h:name:id. - The powder plot is updated after every least-squares cycle (a hook called inside the minimiser), and Rw is drawn per cycle: the FullProf-style live display of R14 exists here too. - Profiles: Finger–Cox–Jephcoat pseudo-Voigt with Thompson–Cox–Hastings widths (CW); back-to-back exponentials ⊗ pseudo-Voigt (TOF, pink beam); fundamental parameters are used only to make instrument files. - Background: eight functions plus Debye diffuse terms, background peaks, a measured background histogram, mouse-set fixed points and an automatic baseline (pybaselines). - Minimiser: Levenberg–Marquardt on an analytic Hessian summed per histogram, with SVD against correlations; parameter limits; a "parameter impact" tool; s.u. propagated into any expression. - Breadth: magnetic structures through Bilbao k-SUBGROUPSMAG, (3+1)D superspace, spherical-harmonic texture, rigid bodies, PDF, small-angle, reflectometry, 2D images, sequential and parametric fits. Stacking faults are simulated with DIFFaX but cannot yet be fitted. - Documentation is 62 tutorials and context help, with no printed manual.

L0082026-10-08decision

The five programs to study: FullProf, GSAS-II, TOPAS, Jana2020, MAUD

The five most used of the nine on the long list, chosen on measured evidence recorded per program in data/programs.yml and shown as two tables on the Background page. The evidence is citations of each program's reference paper(s) per database, what the neutron and synchrotron facilities name or ship, and what the instrument makers ship. No published survey of program use was found. The rule: rank by the citations of the program's own reference papers, and let facility and vendor evidence decide close cases. A program whose count could not be checked, or cannot be separated from another program's, is not shortlisted on this evidence. FullProf (1993 paper: 20,552 Google Scholar, 11,926 Web of Science; ILL, PSI, ALBA), GSAS-II (GSAS-II 2013: 3,393 and EXPGUI 2001: 7,720 on Semantic Scholar; APS 11-BM, Diamond I11, ALBA) and TOPAS (2018 paper: about 2,263 Google Scholar; the program Diamond I11 mainly supports; Bruker's package) lead clearly. Jana2020 is fourth (Jana2006 paper: 4,071 on Semantic Scholar, about 500 a year by its authors' account), with the caveat that Jana's counts mix single-crystal and powder use. It is kept because it is the only program on the list built around superspace (modulated, composite, magnetic) powder refinement. MAUD is fifth and the closest call (1999 paper: 1,336 Google Scholar, 549 Semantic Scholar; the only program on the list built around combined texture, stress and microstructure analysis). Set aside: RIETAN-FP, whose Google Scholar count (3,149) is higher than MAUD's but belongs to a paper that also introduces VESTA, so its own share cannot be separated; HighScore Plus, shipped by Malvern Panalytical but with no citation count that could be checked (the laboratory-vendor side is in the five through TOPAS); Profex/BGMN (94, Crossref, old snapshot); SmartLab Studio II (PDXL), Rigaku's package, with no peer-reviewed reference paper. Limits: the session's network policy blocked the citation APIs (Crossref, OpenAlex, Semantic Scholar, Europe PMC) and the facility and journal pages, so every number was read from a web-search result quoting the page, with the snapshot date unknown. Databases disagree widely (FullProf: 20,552 Google Scholar, 2,486 Semantic Scholar). ISIS and ESRF pages naming a program were not found. Missing values are marked "not checked". Before the choice is relied on beyond phase 0, it should be re-run from the databases directly, and HighScore Plus and RIETAN-FP are the first to re-examine.

L0072026-10-08decision

The site published from an empty public repository; the sources stay private

GitHub Pages cannot serve a private repository on the free plan, and the sources (core, app, data) are to stay private. So, as with the difes test ledger, the site is served from a separate public repository, diff-ref-struct-site, which holds nothing but the rendered pages. Unlike the difes twin, it is filled by an Action of the private repository, not by a script on the Mac: every push to main that touches ecosystem/ builds, checks and renders the site with Quarto 1.10.18 and replaces the public repository's content whole. L0022026-10-08finding

How the difes ecosystem is built, the pattern to follow

The difes project lives in three repositories side by side. difes is the physics core in Python: no GUI imports, every feature with a test and a command-line path, a README with conventions, a CHANGELOG generated from the site. difes-shell is a thin Tauri 2 window that starts the core as a local server and draws what it returns; no physics in the shell. ecosystem_site is a Quarto website (theme none, the family design kit) whose navigation, log, release notes and inventory are generated by tools/build.py from data/*.yml on every render, with a plain LOG.md next to it, a manual in two parts (using the program, theoretical basis), a test ledger, an algorithm registry and a download page.

L0012026-10-08work

The brief

Josu asks for a macOS app, built with Tauri and behaving as a Mac app, for Rietveld refinement of crystal structures from powder diffraction (laboratory X-rays, synchrotron, neutrons), in the line of FullProf and GSAS. Before any code: an inventory of the five most used refinement programs, what they do and how, the features they share and those unique to each, so that the feature set is the most ambitious one. Asked for by name: the refinement core, a live cycle-by-cycle plot as in FullProf, graphics for the data and for the results, interactive background selection, the complete space-group tables, a GUI that writes the control files, and a text editor made for the control and output files. Everything logged and reported, on a website holding the process, the release notes, the findings, the background and the manuals of the core and the app, worked the way the difes project is. The brief is kept verbatim and organised into nineteen requirements (R01–R19) on the Brief page.
