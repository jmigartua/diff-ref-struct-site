Files

Files

Every kind of file in a project started in the app (R27, L091): its folder and name, what it holds, its format, and the files that do the same in FullProf and GSAS-II. The core, the command line and the app take their names from the same file, as they take the parameters' names from the parameter dictionary. A project that comes from FullProf keeps FullProf's names.

23 kinds of file in a project started in the app, each with its folder, name, role, contents and format, and the files that do the same in FullProf and GSAS-II. Names marked proposed await Josu's acceptance (L091); a project that comes from FullProf keeps FullProf's names. Generated from data/files.yml; do not edit by hand.

Principles

  • Readable names, no numeric codes: a file says what it is in words, never FullProf's CODFILn, _calc or 1.fst (R27).
  • Phases by their names, not their numbers: {phase} is the phase's name as the control file gives it.
  • One place per role: a folder for each kind of input and output, so that the project's folder holds the control file and little else.
  • Versions by their time: a version or a result is named by the control file and the time it was made, so that names sort in time and never collide.
  • Measured files keep their own names: the data are the instrument's, and renaming them would lose the link to the lab book.
  • Spaces are allowed, as in the versions decided in L080: every file is a name a person reads; the command line quotes them.

The kinds

Control file

control

Name {project}.drc (extension drc)
Role control
Contents The refinement: the pattern and its data file, the phases and their atoms (or symmetry modes), what is refined, the cycles, the conventions.
Format diff-ref-struct control file: a strict subset of TOML 1.0 with the parameter dictionary's names (core/src/control)
FullProf CODFIL.pcr, the control file (FullProf_Manual.pdf, p. 8)
GSAS-II the project file NAME.gpx, which holds the controls, the data and the results together (a Python pickle)
Written by drs convert; the app's Editor
Status decided (L070: the extension .drc; L099: the name, the project's for the first control file, the user's for the others)
Why this name The file the user works on stays in sight at the top of the project's folder; named after the project, it is found without looking.

Measured data

data

Name Data/{original} (extension any the registry reads)
Role data
Contents The measured pattern(s) as the instrument wrote them, never changed.
Format the instrument's (31 formats, core/src/formats)
FullProf CODFIL.dat or the file named after 'Files =>' (FullProf_Manual.pdf, p. 8)
GSAS-II imported into the .gpx; the file itself stays where it was
Written by the app (a copy, when the user asks to copy the data into the project; W2)
Status decided (L099)
Why this name Measured files keep the instrument's name; a Data folder keeps them apart from what the refinement writes.

Data after the operations

processed_data

Name Data/{data} processed.xys (extension xys)
Role output
Contents The scan after the control file's data operations (masks, smoothing, rebinning, …): x, y, \(\sigma\).
Format FullProf's XYDATA (Ins = 10), written by formats::write (L088)
FullProf none: FullProf has no data operations; WinPLOTR writes the treated pattern to a file of the user's name
GSAS-II none: the operations change the data inside the .gpx; export as .xye (G2export_pwdr.py L112)
Written by drs data apply --out; the .pcr export (as {control}.xys in the FullProf folder)
Status decided (L099)
Why this name Next to the data it comes from, named by it, and plainly not the measured file.

Background points

background_points

Name {stem} background.drb (extension drb)
Role input
Contents The background points (2\(\theta\), intensity) and their interpolation, picked by the user (R26), on a data file opened alone or for a control file.
Format diff-ref-struct background file (format = "diff-ref-struct background 1", interpolation, points; core/src/background.rs)
FullProf the points in the .pcr (Nba \(\ge 2\)) or CODFIL.bac (Nba = 1, FullProf_Manual.pdf, p. 8)
GSAS-II the fixed background points of a histogram, in the .gpx
Written by drs background store; the app's background tool
Status decided (L081: the format and the extension .drb; L099: the name; L116: one kind, {stem}, Josu's decision on the app's request 29)
Why this name One kind whether or not a control file exists: points picked on a data file opened alone are named by its stem, and the control file made from it takes the same stem, so the file keeps its name and its link; two refinements in one project keep their own points.

Derived pattern of a plot set

derived_data

Name Plots/{set} {operation}.xys (extension xys)
Role output
Contents The sum, average or difference of members of a plot set on a common grid, with \(\sigma\), its '!' lines naming the members, each with its value of the series variable and the source of that value (Plots' PL9).
Format FullProf's XYDATA (Ins = 10): six header lines (XYDATA, TITLE, the derivation, the columns), the members as '!' lines, then x, y, \(\sigma\); read back by the registry with negative y kept (an xye file would lose them: GSAS-II reads y \(\le 0\) as no weight). Whether FullProf skips the '!' lines after the header is not stated in its manual (not checked)
FullProf none: WinPLOTR writes its Summation, Difference and Average to a file of the user's name (its guide p. 30)
GSAS-II none
Written by drs plots derive (plots::derived_text)
Status proposed (L175)
Why this name Beside the plot set it comes from, named by it and by the operation, and in Plots/ so that it is never taken for a measured file in Data/.

Plot set

plot_set

Name Plots/{set}.drv (extension drv)
Role input
Contents Several data files as one set (Plots' PL12): the members (each file relative to the project's folder, a scan, a value of the series variable typed or read from a temperatures file, with its source (PL23), visible, opacity, colour), the variable's name and unit, the x quantity, the y scale, the order, the displacement rule, the reference member, the windows.
Format the control file's TOML subset (format = "drs plot set 1"); what is not written is the core's default
FullProf none: WinPLOTR's .buf lists the files of a set, one per line, with a comment (its guide p. 19, §5.1.4), and keeps nothing else
GSAS-II none
Written by drs plots save (plots::SetFile::to_text); read by plots::SetFile::read
Status proposed (L192); the extension is Josu's to confirm (plots/DESIGN.md §2.2)
Why this name Beside the derived patterns it makes, in Plots/, so that a figure is made again from its file (Publish's source, PL15) and a script opens it as a .buf.

Structure

structure

Name Structures/{phase}.cif (extension cif)
Role input
Contents A starting structure for a phase: cell, space group, atoms.
Format CIF (IUCr)
FullProf the atoms of each phase in the .pcr; a CIF converted with CIF2PCR or read with the CFL format
GSAS-II a phase imported from a CIF into the .gpx (imports/G2phase_CIF.py)
Written by the app (a CIF dropped on the data, W5 proposal)
Status decided (L099)
Why this name Phases by their names: a project with two phases has two files a reader recognises.

Symmetry-mode analysis

modes_analysis

Name Structures/{phase} AMPLIMODES.txt (extension txt)
Role input
Contents AMPLIMODES's output for a phase: parent and distorted structures, transformation, reference structure, modes and amplitudes, the block for FullProf (R29).
Format AMPLIMODES's text output, as the Bilbao Crystallographic Server prints it (read by modes::read_amplimodes)
FullProf none: its block for FullProf is pasted into the .pcr (V_MODES, A_MODES)
GSAS-II an ISODISTORT CIF read as a phase with its modes
Written by the user (saved from the server)
Status decided (L099)
Why this name The modes' source kept beside the phase's structure, with its reference metric, so that the normalisation can be checked again.

Instrument resolution

resolution

Name Instrument/{instrument}.irf (extension irf)
Role input
Contents The instrument's peak widths (U, V, W, X, Y, Z or a table), measured on a standard.
Format FullProf's resolution file, read as it is (FullProf_Manual.pdf, p. 70)
FullProf the .irf named on line 6 of the .pcr (Res ≠ 0)
GSAS-II the instrument parameter file NAME.instprm (GSASIIdataGUI.py L1873)
Written by the user (a library of resolution files by instrument, W5 proposal)
Status decided (L099)
Why this name Named by the instrument, not by the sample: one file serves every project measured there.

Version of the control file

version

Name Versions/{control} {time}.drc (extension drc)
Role version
Contents The control file exactly as it was at that time, never rewritten, locked.
Format the control file's
FullProf CODFIL.new, the last one only (FullProf_Manual.pdf, p. 8)
GSAS-II none in its code (the .gpx is written over)
Written by the app (before and after a refinement, on demand)
Status decided (L080)

Refinement log

refinement_log

Name Versions/{control} refinement log.md (extension md)
Role version
Contents One entry per refinement step, appended: time, versions, parameters freed, cycles, \(\chi^2\) and Rwp before and after, the warnings accepted, the user's note.
Format plain text (Markdown)
FullProf CODFIL.out and CODFIL.sum, written over at every run (FullProf_Manual.pdf, p. 9)
GSAS-II the listing NAME.lst, written over at every refinement (GSASIIstrMain.py L462)
Written by the app
Status decided (L080)
Why this name A record that is never rewritten, readable outside the app, next to the versions it names.

Results of a refinement

results

Name Results/{control} {time} results.cif (extension cif)
Role output
Contents Everything a refinement produced (R28): the agreement factors, the refined parameters with their standard uncertainties, the control file, every phase (cell, symmetry, atoms with their uncertainties, R_Bragg), the profile (2\(\theta\), Yobs, its weight, the background, Ycal, each phase's curve), the excluded regions, the reflections (h k l, multiplicity, d, 2\(\theta\), FWHM, |F|², I calc, I obs partitioned by the model and its \(\sigma\)).
Format powder CIF (pdCIF): the IUCr's DDL1 core and powder dictionaries where they name an item, the local prefix _drs_ for the rest; one data block for the whole, one per phase, one for the pattern, linked by _pd_block_id (core/src/results.rs)
FullProf CODFIL.prf (profile), CODFIL.out, CODFIL.sum, CODFILn.hkl
GSAS-II the .gpx itself; CIF and .csv exports (G2export_CIF.py L4827)
Written by results::write (drs results); the app after each refinement (the record)
Status decided (L092: pdCIF; L099: the name)
Why this name One results file per refinement, named by its control file and time like the versions, so that each version has its results; a CIF that GSAS-II and the journals read.

CIF for deposition

deposition_cif

Name Results/{control} {phase}.cif (extension cif)
Role output
Contents A phase's refined structure with its uncertainties, the experiment and the agreement factors (L083).
Format CIF (IUCr core and powder dictionaries)
FullProf CODFIL.cif / CODFILn_dis.cif (Rpa, news)
GSAS-II the project's CIF export (G2export_CIF.py L4827)
Written by drs cif (cif_write::deposition); drs results, with the results file (results::write)
Status decided (L099)
Why this name Named by the refinement and the phase, so that two phases give two files and a journal's reader knows which is which.
